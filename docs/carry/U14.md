## Fixed here
- **U13b-5, sideways scroll at 280 px (e2e flake).** Not the "Data updated" badge. The run-3 traces show the extra 20 px
  is `CardLinksCanvas`: a bare `<canvas>` is 300×150 until `useCanvas` sizes it on the first animation frame, and 300 px
  on a 280 px page scrolls it sideways. On a slow or busy CPU the test measured before that frame. The canvas now starts
  at `width={0} height={0}`. Local probe at 280 px, 4× CPU throttling, polling every frame from navigation: before, the
  overflow hit on every run; after, 0 hits in 4 runs each on `/` and `/dashboard/`. The e2e assertion is unchanged.
- **U13b-2, character import CLS.** The import box is now one `<details>` for the page's whole life. It collapses to
  "Load another character" as soon as an import starts (`busy`), so the skeleton sits where the panels will land. A failed
  import re-opens it with the URL and the error. The bar stays mounted throughout, so a failed URL is kept. Probe at
  390×844, Fast 3G + 4× CPU, proxy held 1.5 s: CLS **0** for `?import=` and for a typed URL (was 0.11).
- **ImportBar cleared `busy` on success** (found while fixing U13b-2). On a typed URL the bar set `busy` false as soon as
  the fetch returned, so the skeleton vanished for the whole analysis and the empty state flashed. It now clears `busy`
  only on failure; on success the page owns it until the analysis lands (as `?import=` already did).
- **U13b-3, scroll-spy at the end of the page.** `useScrollSpy` marks the last section current when the page can't
  scroll further (`atPageBottom`, 2 px slack), checked on IO entries and on a rAF-throttled scroll listener. Unit tests
  in `apps/web/test/scrollSpy.test.ts`.
- New e2e tests in `character.spec.ts`: a typed import collapses the box while busy (skeleton shown, box stays closed
  after); a failed import keeps the box open with the URL and the error. Left to CI.
