### SW design for U12 (A3-1)
Files: `apps/web/public/sw.js`, `apps/web/src/components/ServiceWorker.tsx`, `apps/web/next.config.ts`, tests in
`apps/web/test/serviceWorker.test.ts`, browser check `scripts/sw-update-check.cjs`.

- **Query params.** The page registers `${BASE_PATH}/sw.js?v=<data>&b=<build>` with scope `${BASE_PATH}/`.
  `v` = `NEXT_PUBLIC_DATA_VERSION` (hash of the data files), `b` = `NEXT_PUBLIC_BUILD_ID` (both set in `next.config.ts`).
  A change to either makes a new worker. The worker reads them from `self.location` (fallbacks `v3` / `b0`).
- **Cache names.** `poe2-shell-<build>` (app shell, keyed on `b`) and `poe2-data-<data>` (keyed on `v`). A code-only deploy
  drops the old shell and keeps the ~2.7 MB data cache.
- **Prune rules.** `pruneOldCaches()` deletes every cache whose name starts with `poe2-` and is neither the current shell nor
  the current data cache. It runs (a) on `activate`, before `clients.claim()`, and (b) again on the first fetch each worker
  start handles, because the old worker's in-flight writes can recreate the cache just deleted.
- **Install precache.** `cacheOpenPages()` (best-effort, errors swallowed, then `skipWaiting()`): fetch the root `./` plus
  every open same-origin window's URL with `cache: 'no-cache'`, store the HTML in the new shell cache, and fetch + store
  every `/_next/static/…{js,css,woff2}` the HTML references. Without it, an offline reload straight after an update fails
  (`ERR_FAILED`), because the reload is served by the old worker and the new shell cache stays empty. Data files are
  **not** precached (2.7 MB on a possibly metered first visit); they are cached on first use.
- **Strategies.** Data files (`passive-tree.json`, `mod-tiers.json`, `monster-stats.json`): cache-first, store only
  `200`. Everything else same-origin GET: network-first, store only `200`, offline fallback to the cache, and navigations
  fall back to the cached root shell.
- **Never cached.** Live requests: hostname matching `ninja-proxy` or `poe.ninja`, or a path containing `/api/`. Also
  non-GET requests and other origins (passed through untouched).
- **Localhost.** `ServiceWorker.tsx` skips registration when `location.hostname` is `localhost` or `127.0.0.1`, so a
  stale worker never serves an old build during dev.
- **Testing trick.** To exercise the worker locally, serve `apps/web/out` and open it as `http://sw.localhost:<port>`:
  `*.localhost` resolves to loopback and is a secure context, but isn't `localhost`, so registration runs.
  `scripts/sw-update-check.cjs` does this (first load → rebuild → reload → offline reload → offline unvisited route);
  set `SW_CHROMIUM` to a Chromium binary in the cloud (`/opt/pw-browsers/chromium-*/chrome-linux64/chrome`).
