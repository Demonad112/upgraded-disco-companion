## Fixed here
- **Service worker failed every request when Cache Storage errors** (found by this QA run). In a Chrome profile whose Cache
  Storage throws (`caches.open` → `UnknownError: Unexpected internal error`; here a profile under a deep Windows Temp path,
  in the wild a damaged profile or storage fault), the first visit loaded, then every navigation and asset failed with
  `net::ERR_FAILED`, online too, and stayed broken across restarts. Seen on production and on the pre-#65 preview, so it
  predates this programme's last wave. Cause: `networkFirst` / `cacheFirst` called `caches.open` before their `try`, so
  `respondWith` got a rejected promise. Fix in `apps/web/public/sw.js`: open, match and put go through small helpers that
  turn a cache error into "no cache"; prune errors are swallowed. A3-1's design (cache names, strategies, prune rules,
  install precache) is unchanged. New unit test "answers from the network when Cache Storage itself fails" (fails on the
  old worker, passes now). Browser check: in the same broken profile against the local build, the old worker failed nav 2
  and 3, the fixed one served all of them, including after a relaunch.
- **Compact mode scrolled 4 px sideways on Dashboard and Atlas below 640 px** (found by the sweep). The sticky tab rows bleed
  with `-mx-4 px-4` (16 px), but compact mode sets `main { padding: 0.75rem }` (12 px). Both rows are tagged `data-bleed`,
  and one rule next to the compact `main` rule in `globals.css` sets their bleed to 0.75rem in compact mode below `sm`. The
  "do not scroll sideways" e2e test now also checks compact mode at 280 and 390 px (no assertion removed). It fails on the
  unfixed build in the desktop project (`compact dashboard/ at 280px`, 4). The compact checks are their own test, so the
  original test stays inside the 30 s timeout. The mobile project can't see it: with `isMobile`
  the layout viewport widens to the content, so `scrollWidth - innerWidth` stays 0 there.
- U3-1: `.eyebrow` kept, with a comment. It has the same values as `.label-metric` but sits in `@layer components`; callers
  pair it with colour utilities (`eyebrow text-accent`, `text-warn`), which beat a layered class and would lose to the
  unlayered `.label-metric`. Aliasing would recolour them.
