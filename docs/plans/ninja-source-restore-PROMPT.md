## What a code can and cannot restore (decide each, recommend one answer)
A PoB code carries poe.ninja's *computed numbers and config*. It does not carry what the old poe.ninja path also used:
- per-stat `breakdowns` (attribution, "What each item is holding up", resistance rebalancing),
- structured mod ids per item line (gear tiers without text matching),
- the ladder / offence grade.
So there are three levels of "as it was". The plan must price and recommend among them:
1. **Numbers-only:** read the poe.ninja-origin code through the existing PoB reader into a `ninja-baseline` view (no new engine). Cheap. Loses breakdowns, mod ids, ladder.
2. **Full legacy path:** resurrect the deleted fixtures from git, re-enable the `source: 'poe.ninja'` regression tests and goldens as a separate suite, and keep the model JSON path alive for any captured poe.ninja model. Faithful for regression; no live fetch.
3. **Live:** the URL import via `services/ninja-proxy`, blocked by NP1-1. Out of scope until sanctioned access returns; only keep it dormant.
