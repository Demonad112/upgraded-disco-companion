# PoB2 oracle fixtures

`<league>/<name>.code.txt` is a pasted PoB2 export code. `<name>.oracle.json` next to it is what real PoB2 computes for that code at the pinned commit (`vendor/pob2/PIN.json`). It is generated by `npm run pob2:oracle`, never edited by hand (the edit hook blocks it).

| League | Fixture | Notes |
|---|---|---|
| `forbidden-rites` | `main` | The owner's main build (Monk / Martial Artist, level 90; the same code B2 seeded as `seed-monk`). Its export is stale against PoB 0.23.1: 17 stats differ, e.g. TotalDPS 125,658 embedded vs 125,919 recomputed and every maximum hit about 8% lower now (physical 5,004 → 4,597); Life, ES and resistances match. |
| `forbidden-rites` | `current` | The same character after the owner's 2026-11-24 changes, exported from the PoB2 app; the end-to-end fixture for the per-skill table (B9). Also stale: 17 stats differ, TotalDPS 186,706 embedded vs 203,790 recomputed, physical maximum hit 5,182 → 4,751; Life, ES and resistances match. |

Oracle shape (keys sorted, 2-space indent):

- `pobVersion`, `pinCommit`, `loadError` (`null` when PoB loaded the build).
- `stats`: every `displayStats` / `extraSaveStats` key present in `build.calcsTab.mainOutput`, whatever the skill-flag filter. `childStat` keys are dotted (`MainHand.Accuracy`); minion stats are `Minion.<stat>`. Non-finite numbers are the strings `inf`, `-inf` and `nan`.
- `fullDpsSkills`: `mainOutput.SkillDPS` rows (`name`, `count`, `dps`, `value = dps × count`, `skillPart`, `source`).
- `export`: `PlayerStat`, `MinionStat` and `FullDPSSkill` parsed from `build:SaveDB()`, i.e. what PoB would write into an export now. Values are numbers wherever PoB wrote one.

`../pob2-oracle.test.ts` (vitest, no Lua) holds `readPobSnapshot` to these files: every embedded stat PoB still computes the same must match exactly, and the rest is the analysis finding "Stale export: re-export from current Path of Building" (`Analysis.staleExport`, given `AnalyzeOptions.pobRecomputed`). The golden `../golden/pob-code-main.expected.json` pins that finding.

`<name>.groups.oracle.json` (CP-7) is written by `tools/pob2/groups.lua` for each code here and for `../ninja-legacy/main-ninja.code.txt`: `groups` is the code's `<Skill>` group count, `rows` one per (group, active skill) with PoB's main output when that group is selected (`skill`, `enabled`, TotalDPS, CombinedDPS, AverageDamage, Speed, crit, DoT keys, cost, cooldown, `mainHand` hit averages). It is CI-only ground truth: a code stores PlayerStats for its main group only, and the site never shows or simulates the other rows (B9). `../pob2-groups-oracle.test.ts` checks the main group's row against the code, a row per group, and each group's skill against `allGems`.

Regenerate after a PoB bump or a fixture change: `npm run pob2:oracle`. Review the diff and commit it with the cause. CI's `pob2-oracle` job runs `npm run pob2:oracle -- --check` and fails on any byte difference. Archived leagues (`archive/<league>/`) are not regenerated (B7).
